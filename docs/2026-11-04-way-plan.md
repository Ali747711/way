# Way v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Way v1: a static Next.js app that serves one finite daily set of five problems and one weekly deep problem from a reviewed content bank, plus the offline scripts that produce that bank.

**Architecture:** Three layers share one Zod problem schema. Offline scripts under `scripts/` generate, verify and schedule problem files under `content/`; a build step assembles per-day JSON files into `public/content/`. The static Next.js app fetches today's file, runs the one-at-a-time flow with pure reducers over a localStorage store, checks answers in the browser, and runs code problems in a Web Worker. Nothing runs on a server.

**Tech Stack:** Node 24, npm, Next.js App Router with `output: 'export'`, TypeScript strict, Tailwind CSS, shadcn/ui, Zod, react-markdown, Vitest + Testing Library (unit), Playwright (e2e), tsx + esbuild (scripts, worker bundle), Vercel AI SDK + `@ai-sdk/anthropic` (generation, offline only).

**Spec:** `docs/2026-11-04-way-design.md`

## Global Constraints

- TypeScript everywhere, `strict: true`, no `any`. Prettier: 2-space indent, single quotes, no trailing commas. Named exports, except React components and Next pages.
- No server-side state, database, account, analytics, runtime AI call, or network request other than fetching `/content/**.json` and `/runner.worker.js`. Nothing leaves the browser (spec §7, §8.3).
- Fixed daily order and difficulty: words 1, logic 2, math 3, code 3–4, create 3–4. Deep problem difficulty 5. Five problems per day (spec §9.2).
- Hints: exactly 3 on a daily problem, 5 on a deep problem; every hint ends with `?`; no hint contains an accepted answer (spec §9.3, §9.6).
- Attempts: exact 3, number 3, choice 1, code unlimited, open 1; deep problems unlimited. Invalid submissions (empty, not a number, outside word limits) consume no attempt (spec §8.2).
- Fixed copy: `Hint 1 of 3`, `Solved`, `Not quite`, `Out of attempts`, `Show the solution? You can't retry today.`, `passed 5 of 7`, `Timed out`, `That's today.`, `Come back tomorrow.`, `Nothing scheduled for today.`
- Problem status flow: `draft` → `verified` (verify script) → `approved` (owner, by hand) → `published` (schedule script). Only `published` problems reach `public/content/` (spec §9.4).
- A day is the device-local date `YYYY-MM-DD`; a week is the ISO week `YYYY-Www`. Sessions are keyed by these; a key mismatch on load or on Next starts a fresh session and discards the old one (spec §8.2).
- Files under 400 lines, functions under 50. Vitest coverage over `lib/` at 80% or above.
- Conventional commit messages. No attribution trailers.
- The dev server must be started inside tmux (a global shell hook blocks it otherwise): `tmux new-session -d -s way "npm run dev -- -p 3100"`. Playwright's `webServer` spawns it itself and is not affected.

## Review Focus

1. Empty, whitespace-only, or non-numeric submission on an exact/number problem: no attempt consumed, no `Not quite`, field stays editable. (Task 4, Task 10)
2. Corrupt JSON or an older shape in localStorage: the app starts with empty state instead of crashing. (Task 5)
3. No day file for today's date: the `Nothing scheduled for today.` screen, never a blank page or an error. (Task 10)
4. User code that never returns: Run reports `Timed out` within the limit, the page stays responsive, and a second Run works. (Task 8, Task 10)
5. Reload mid-problem: revealed hints, used attempts and a shown outcome all persist, not just the draft. (Task 5, Task 10)
